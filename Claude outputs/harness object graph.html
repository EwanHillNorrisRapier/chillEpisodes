Direct counts the procedures and functions that name the object themselves. Transitive counts everything that reaches it through any chain of references, which is the number that matters when a column name turns out to be wrong.

Nothing on the CSPExecuteGenericGraph path reads a column of the three metric tables or of CSPLoadLog and CspExportTablesList, so a graph run is unaffected by those five being wrong. CSPExecutionMasterGraph, CSPExecutionMasterGraphNode and CSPExecutionStrings are a different matter: all three sit on the execution path.

Three things worth knowing

One cycle. CSPGraphExec and CSPExecGraphNodeTypeGraph call each other. That is a graph node of type 1 running a child graph, which re-enters the node loop. Every other reference runs one way.

Twenty-four entry points. Nothing inside the harness calls them. Most are meant to be invoked from a graph node's own SQL, CSPTableCopy and CSPValidateSourceRecords among them, so a node string is the only thing that would reveal a broken one.

One table nothing uses. CSPExecGraphPrep creates CSPExecutionGraphNodeSetup and no object ever reads or writes it. It is dead weight carried across with the port.
